# Интеграция Tsuev и проверка Gemini

Обновление: 17 ноября 2026.

## Выполнено

По прямому выбору пользователя DeepSeek переключён на `Tsuev/opencode-deepseek`.
Текущий HEAD проверен через `git fetch`: `2e3c81d7ea47a5fabb5aa7fa2a4f45cf681981c9`.
Проект установлен в `.services/opencode-deepseek`, в отдельное окружение Python 3.13.
`pip check` не выявил конфликтов. Установка не меняла глобальный Python или настройки opencode.
Версии установленных зависимостей сохранены в `examples/deepseek-dependencies.macos-arm64.txt`.

Адаптер `TsuevDeepSeekAdapter` использует non-stream текстовый endpoint. Переход к native/emulated
tool calls запрещён. Сеансы передаются явно; интерпретатор и исполнитель проверяются по ID
диалога, даже если отличаются ID отдельных сообщений. Reporter продолжает сеанс интерпретатора.
`503 login_required` и `Retry-After` распознаются, автоматических повторов нет.

Добавлены команды `bridge login`, `bridge start`, `bridge status` и отдельный явный
`scripts/setup_deepseek.sh`. Launcher проверяет закреплённую ревизию и отсутствие изменений
tracked-кода перед запуском. Сервис слушает только loopback, не получает Gemini-ключ,
использует отдельный Chrome-профиль и не печатает token prefix. CAPTCHA не автоматизируется,
браузерные fingerprint/header overrides не добавлены. Сохранены upstream-паузы/квоты/cooldown;
отключены автоматический вход, фоновый refresh и неявное слияние истории.

## Проверено автономно

```bash
CTF_TEST_DOCKER=1 CTF_TEST_TSUEV=1 python3 -m unittest discover -v
```

**47 тестов прошли, пропусков нет.** [Полный вывод](tsuev-test-results.txt).

Дополнительная проверка запускает настоящий FastAPI endpoint установленной ревизии Tsuev
с подменой только внешней генерации. Проверены формат ответов, две независимые беседы,
продолжение беседы, отсутствие tool calls, ошибки входа и cooldown. Запросов в аккаунт DeepSeek
из этого теста не отправляется. Контейнерные тесты также прошли. В финальном прогоне обнаружено ограничение killpg на хосте; завершение Docker-клиента заменено на адресный process.kill(), а контейнер по-прежнему удаляется через docker rm -f. После исправления полный набор прошёл.

Ключ Gemini вводится скрыто: `--prompt-key` доступен для `run`, `resume`, `live-check`.
Он существует только в памяти процесса и очищается/восстанавливается при выходе, в том числе
при ошибке. Тесты проверяют отсутствие ключа в выводе и передачу только в authentication header.

## Живые проверки Gemini

Предоставленный пользователем ключ использован только для официального Gemini endpoint,
без записи в файл, командную строку запуска процесса или журналы проекта.

- `GET /v1beta/models/gemini-4-hydrogen`: **HTTP 200**, возвращена именно запрошенная модель.
- Две короткие попытки `generateContent` на стандартных настройках завершились ошибкой
  соединения/таймаутом; корректность генерации ими не подтверждена.
- Дополнительная проверка с документированным `thinkingLevel=LOW`, без возврата thoughts:
  **HTTP 503**. Автоматический retry или замена модели не выполнялись.

Таким образом, доступ по ключу к metadata модели подтверждён, а успешной живой генерации
пока нет. Для `live-check` используется `low` с пределом 2048 токенов; основная конфигурация
сохраняет `high` и 8192. Параметры выводятся в конфигурацию, а не меняются скрыто при ошибках.

## DeepSeek: состояние входа

Окно штатного установленного Chrome открывалось для ручного входа через upstream helper.
Пользователь сообщил о проблеме с CAPTCHA. Сессия не получена; затем пользователь явно
попросил **оставить мост без входа**. Попытки авторизации прекращены, сервис не запущен,
живые генерации DeepSeek не выполнялись. Мобильное/настольное приложение не является
реализованным способом авторизации этого моста; перенос токенов из приложения не делался.

Когда пользователь решит продолжить:

```bash
python3 -m ctf_agent bridge login
python3 -m ctf_agent bridge start
# В другом терминале:
python3 -m ctf_agent live-check --provider bridge --config examples/config.toml
```

Ранее сохранённый live-run с сеансами старого неопределённого провайдера не переносится
молча на Tsuev: потребуется новый запуск. Автономные запуски и демонстрация совместимы.
