# Отчёт о выполнении

Дата: 17 ноября 2026. Хост: macOS, Python 3.15.0; Docker Engine 29.1.3. В контейнере Python 3.13, базовый образ закреплён digest в Dockerfile.

## Реализовано

Работающий CLI с командами `run`, `demo`, `status`, `resume`, `journal`, `add-material`, `live-check`; последовательный оркестратор Gemini и две раздельные DeepSeek-роли; строгие JSON-сообщения; SQLite и файловые артефакты; неизменные исходники; приоритетная очередь; ограниченные и нормализуемые изменения вектора; бюджеты; контейнерный Runner; ограниченный HTTP GET-брокер; сохранение и восстановление; раздельные статусы гипотезы, кандидата и проверенного решения.

Gemini REST и текстовый мост подключаются сменным интерфейсом `complete(role, schema, context, session, timeout)`. Fake-реализация проходит тот же валидатор и тот же orchestration loop.

## Проверено автономно

Финальная команда:

```bash
CTF_TEST_DOCKER=1 python3 -m unittest discover -v
```

**37 тестов, 37 успешно, 0 пропущено**: 31 тест протокола/состояния/адаптеров и 6 интеграционных тестов с настоящими контейнерами. Полный результат: [test-results.txt](test-results.txt).

Проверены все обязательные случаи: некорректный JSON, таймаут, отсутствие повторного исполнения при восстановлении, нормализация и нулевая сумма вектора, нейтральность ошибки соединения, приостановка ветки и невозможность автоматического превращения кандидата в успех. Дополнительно проверены восстановление между исполнением и отчётом, неопределённый исход прерванного действия, атомарный rollback финализации, запрет веб-ветки для crypto без материалов, разные сеансы, сокрытие известного секретного значения, отсутствие повторов HTTP-запросов при отказе модели, границы filesystem и блокировка второго процесса.

В реальных контейнерах проверены UID 10001, read-only материалы, отсутствие default network route у команд, отсутствие Docker socket, отдельный полный log при усечённом preview, остановка по пределу вывода, удаление контейнера по таймауту. HTTP-тест использовал временный локальный контейнер-сервер: разрешённый IP:порт работает, другой порт отклоняется, redirect не исполняется. Внешние CTF-сервисы не запрашивались.

Docker-образ успешно собран. CLI `--help` проверен. Финальная демонстрация выполнена двумя командами:

```bash
python3 -m ctf_agent demo --run-dir runs/demo-final --stop-after 1
python3 -m ctf_agent resume runs/demo-final
```

Результат: `verified`, **2 эксперимента, 16 имитированных модельных вызовов, 4 действия**. Сначала `NO_CANDIDATE`, затем `flag{separate_roles_real_experiments}` с совпавшим SHA-256. Категории обеих гипотез — `crypto`. В интеграционном тесте без критерия та же цепочка заканчивается `candidate_unverified`.

Приоритет crypto: `0.8 → 0.7974683544 → 0.8072289157`. Первый шаг опровергает лишь конкретный ключ 0, а не всю криптографическую категорию. Остальные направления нормализуются пропорционально; веб-экспериментов не было.

Сохранённый SQLite/логи/артефакты находятся в `runs/demo-final`. Переносимый пример событий, карточек и векторов: [../examples/demo-journal.json](../examples/demo-journal.json).

## Проверено на реальных моделях

**Живые генерации не выполнялись.** `GEMINI_API_KEY` отсутствует в окружении. `http://127.0.0.1:8000/healthz` вернул ошибку соединения `ConnectionRefusedError`: локальный DeepSeek-мост не запущен. В аккаунты вход не выполнялся, ключи/cookies не извлекались, зависимости сторонних мостов не устанавливались.

Проверены официальная документация Gemini, реальные закреплённые исходники обоих мостов и mock-контракты наших HTTP-адаптеров. Это не заменяет проверку доступности модели для аккаунта, актуальности веб-сессии, качества JSON и гипотез на живой модели. Для неё предусмотрен отдельный `live-check`; подробности и ревизии — [integrations.md](integrations.md).

## Оставшиеся ограничения

- Автономная fake-политика решает только синтетическую single-byte XOR задачу. Универсальные исследования требуют живых моделей.
- Нет проверки на реальном аккаунте Gemini/DeepSeek и реальной удалённой CTF.
- Сетевая функция — только точный IP:порт и один GET/HTTPS GET без redirects. Raw TCP/UDP, HTTP POST и сетевые команды моделей отсутствуют. Контроль сети брокера программный; весь Docker bridge не получает отдельный firewall.
- Нет строгой общей дисковой квоты рабочего bind mount во время команды и дополнительного гипервизора. Ограничены размер отдельного файла, число/размер сохраняемых артефактов, память, CPU, процессы и время.
- Дедупликация использует структуру эксперимента и хеши, но не распознаёт семантически одинаковые перефразированные процедуры.
- Версия новых данных общая для запуска; автоматическое возобновление веток использует явно указанную связь с объектом. Текст `resume_when` не является исполняемым предикатом.
- Синхронное исполнение: статус инструмента можно прочитать после завершения; отдельного background-process API нет. После неопределённого эффекта используется at-most-once без автоматического повтора.
- Подтверждение результата — только явно заданный SHA-256 флага; интеграция с внешним scoreboard и другие форматы флагов остаются расширением.
- Пакет использует POSIX `flock`/signals; нативный Windows не поддержан. Ghidra, интерактивные отладчики и тяжёлые средства анализа не изображаются как доступные.
